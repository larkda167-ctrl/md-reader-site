AGENTS.md とは？ファイルの内容と書き方

更新日: 2026-11-23

AGENTS.md は、Codex などのコード作成や変更を行う AI コーディングエージェント向けの指示が書かれたプレーンテキストファイルです。エージェントは作業を開始する前にこのファイルを読み込むため、プロジェクトのビルド方法、テスト方法、従うべきルールをあらかじめ把握できます。

このファイルは、# や ** などの記号を使ってテキストをシンプルに装飾する Markdown で書かれています。ファイル自体が何かを実行することはないため、開いて読むのは安全です。ただし、編集する場合は別です。エージェントは変更した内容に基づいて動作します。

記載内容

AGENTS.md のサイトでは、このファイルをエージェント向けの README と説明しています。README.md は人間向けに、プロジェクトの概要や始め方を書くものです。一方 AGENTS.md には、README では細かすぎて情報が散らかってしまうような、エージェントが必要とする詳細な内容を記載します。

必須の項目はありません。通常の Markdown なので、好きな見出しを使用できます。サイトでは次のような内容をカバーすることを推奨しています：

  • プロジェクトの概要： プロジェクトが何であるかを数行で説明
  • ビルドとテストのコマンド： エージェントが自分の作業を検証できるようにする
  • コードスタイル： プロジェクトが従う規約
  • テスト手順： 作業完了とみなすためにパスすべき条件
  • セキュリティ上の注意： エージェントが慎重に取り扱うべき事項

コミットやプルリクエストのルール、デプロイ手順なども記載できます。簡単なファイルの例は次のとおりです：

# AGENTS.md

## Commands
- Install: npm install
- Test: npm test (run this before you finish)

## Code style
- Keep user-facing text in src/i18n
## Don't touch
- Files in /generated are created by a script

配置場所

ファイルはプロジェクトのルートフォルダに配置します。ほとんどのプロジェクトではこれで十分です。

複数の独立したパーツで構成される大規模なプロジェクトでは、各パーツの内部にそれぞれ AGENTS.md を配置できます。AGENTS.md のサイトによると、エージェントはフォルダツリー内で最も近いファイルを読み込むため、一番近くにあるものが優先されます：

ファイル 用途
トップフォルダの AGENTS.md プロジェクト全体の指示
サブフォルダ内の AGENTS.md そのフォルダ内の作業に対する指示。その場所で優先される

チャットでエージェントに直接入力した指示は、これらよりも優先されます。あなたからの明示的な要求がファイルを上書きします。

対応しているツール

AGENTS.md は特定の製品に依存しません。Linux 財団傘下の Agentic AI Foundation が現在管理しているオープンフォーマットであり、OpenAI の Codex、Google の Jules、Cursor、Amp、Factory を含む複数のチームの取り組みから発展しました。

AGENTS.md のサイトには、Codex、Cursor、Gemini CLI、GitHub Copilot のコーディングエージェント、Aider、Zed、Windsurf、VS Code など、このファイルを使用する 20 以上のツールがリストアップされています。これがこのフォーマットのポイントです。ツールごとに個別のファイルを維持する代わりに、プロジェクトのルールを一度書くだけで済みます。ファイルが読み込まれていないように思える場合は、各ツールの詳細なドキュメントを確認してください。

AGENTS.md と CLAUDE.md

CLAUDE.md は、Anthropic のコーディングエージェントである Claude Code に対して同様の役割を果たします。プロジェクトの両方のファイルが存在する場合、それらは異なるツール向けに常時適用される 2 種類の指示となるため、お互いに矛盾していないことを確認する価値があります。CLAUDE.md ファイルとはのガイドでは前者を解説しており、コーディングエージェントが作成する .md ファイルではその隣に見つかる他のファイルについて説明しています。

注意点

パスワードや API キーをファイルに含めないでください。このファイルは通常、コードと一緒にプロジェクト内に保存されるため、プロジェクトを閲覧できる人なら誰でも読むことができます。

常に最新の状態を保ってください。エージェントはそこに書かれている内容を信頼するため、古いテストコマンドや、もはや従っていないルールがあると、間違った方向へ進んでしまいます。同じ間違いを2回直していることに気づいたら、1行追加しましょう。

スマホで読む方法

プレーンテキストアプリで開くと、ファイルには # や ** の生記号が表示されます。Android でフォーマットされた状態で読む手順は次のとおりです：

  1. ファイルをスマホに送信します。コーディングエージェントは通常パソコンで実行されるため、Google Drive、メールの添付ファイル、または USB ケーブルを使用します。
  2. ファイルをタップして MD Reader を選ぶか、アプリ内のファイルを開くを使用します。

Google Playで手に入れよう

見出し、テーブル、コードブロックが整形されて表示され、目次を使ってセクション間をジャンプできます。指示ファイルによく見られる <example> などのタグは、消えることなくそのまま表示されます。Drive の使用方法については、Google Drive から .md ファイルを開く方法をご覧ください。

MD Reader は Codex やその他のコーディングツールとは接続されておらず、パソコンと同期もしないため、読んでいるのはコピーです。ファイルが変更されたら、再度送信してください。編集をタップしてコピーを変更することはできますが、ファイルをパソコンに戻すまでエージェントはその変更を確認できません。
